# Security Model

本页记录 Zun 当前的最小安全模型与副作用边界。

Phase 11 的目标不是立即实现沙箱，而是先把当前真实行为文档化，让社区明确知道：哪些能力默认开放、哪些能力未来可能受限、哪些改动必须进入安全讨论。

## 当前默认能力模型

当前 Zun 默认采用以下模型：

- 默认信任本地执行环境
- 没有沙箱
- 没有权限系统
- 没有 capability-based runtime

这意味着：只要脚本能够运行，它通常就可以直接访问运行进程本身可访问的文件系统、环境变量和网络服务入口。

## 当前副作用入口

当前仓库中已存在的主要副作用入口包括：

- 文件 I/O
- 环境变量读取
- 标准输入读取
- HTTP 服务暴露
- HTTP 出站请求
- 数据库连接与 SQL 查询
- 模块文件加载

下面分别记录当前边界。

## 文件读取与写入

### 当前行为

Zun 当前支持文件相关能力，包括：

- `std.fs.read_text(...)`
- `std.fs.read_lines(...)`
- `std.fs.write(...)`
- `std.fs.append(...)`
- `std.fs.delete(...)`
- `std.fs.exists(...)`
- `std.fs.size(...)`
- `std.fs.is_dir(...)`

这些能力当前直接映射到底层文件系统访问，不经过沙箱。
当前实现已经通过 runtime intrinsic 层集中管理 `fs/env/config` 这类宿主能力，但默认 policy 仍是 allow-all。

legacy 语法 `$<<FILE(...)` / `$>>FILE(...)` 目前仍存在兼容窗口，但安全边界应以 `std.fs` 这组能力来理解。

### 当前边界

- 路径由脚本提供
- 访问范围默认受宿主进程文件系统权限约束
- 没有项目根目录级别的读写限制
- 没有只读模式
- 没有路径白名单

### 风险说明

当前实现下，脚本可以读取或写入宿主进程有权限访问的任意路径，这属于默认开放能力。

## 环境变量访问

### 当前行为

Zun 当前支持：

- `$<<ENV("KEY")`

运行时直接调用宿主进程的环境变量读取能力。
当前该能力已统一进入 runtime intrinsic 层。

### 当前边界

- 读取范围默认等于宿主进程可见的全部环境变量
- 没有白名单
- 没有命名空间隔离
- 没有按模块或运行模式区分权限

### 风险说明

环境变量常包含密钥、令牌、路径和部署信息，因此这是高敏感能力。当前实现把它视为默认开放能力。

## 标准输入读取

### 当前行为

Zun 当前支持：

- `$<<LINE(...)`

这会直接从宿主进程的标准输入读取一行内容。

### 当前边界

- 没有交互能力开关
- 没有非交互模式隔离
- 没有按运行模式单独限制

## HTTP 服务暴露

### 当前行为

`serve` 模式下，Zun 可以：

- 启动 Axum HTTP 服务
- 绑定配置中的 host / port
- 暴露脚本注册的路由
- 暴露静态文件目录
- 通过 `@SET_HDR(...)` 配置 HTTP 响应头
- 通过 `@CORS(...)` 配置全局、HTTP 块级或路由级 CORS 响应策略
- 通过 `package.toml` 的 `[server.auth]` 配置启用请求级认证与授权

当前 `serve` 认证入口支持：

- Cookie Session
- `Authorization: Bearer <token>` JWT
- 基于路由规则的最小授权检查（认证态、角色）

运行时会在每个请求开始时解析认证态，并把结果注入请求级 auth context。
`std.auth.session`、`std.auth.jwt`、`std.auth.guard` 都从这个请求级上下文读取当前 principal / session / claims。

HTTP handler 默认可访问当前运行时中已经开放的能力，包括：

- 读取请求头
- 访问项目配置
- 调用 runtime 内已有函数和模块
- 间接使用文件 I/O、环境变量和模块加载能力

### 当前边界

- 没有请求级能力沙箱
- 没有 route sandbox
- 没有静态资源目录白名单之外的额外约束机制
- 没有把 handler 与普通脚本能力区分开
- `@SET_HDR(...)` 与 `@CORS(...)` 当前只影响 HTTP 响应元数据，不提供新的权限控制或隔离能力
- 当前 auth 只提供统一的认证态注入与最小路由授权，不等于 capability-based permission system
- 当前 route auth 规则已接通：
  - `require = "authenticated"`
  - `roles_any = [...]`
  - `roles_all = [...]`
  - `permissions_any = [...]`
  - `permissions_all = [...]`
  - `claims_all = { ... }`

- 路由授权规则支持更具体规则覆盖更宽泛规则，例如前缀规则 `/admin/*` 可被更具体的 `/admin/health` 覆盖
- Session store 当前可落到内存、SQLite、Postgres，但这些后端都运行在宿主进程已有文件系统 / 网络权限之上

### 风险说明

一旦启动 `serve`，脚本就从“本地工具脚本”变成“对外暴露服务”。因此 HTTP 能力不仅是网络入口，也会把其他副作用能力暴露给远程请求路径。

## HTTP 出站请求

### 当前行为

Zun 当前通过 `std.http` 原生模块支持同步 HTTP 客户端调用，包括：

- `http.get(...)`
- `http.post(...)`
- `http.put(...)`
- `http.delete(...)`
- `http.request(...)`

这些调用底层直接使用宿主进程的网络能力发起出站请求，当前不经过额外权限确认，也没有按域名、协议或端口做白名单限制。

### 当前边界

- 请求目标由脚本提供
- 默认可访问范围等于宿主进程可访问的网络范围
- 没有请求目标白名单
- 没有按模块、运行模式或 HTTP handler 区分网络权限
- 请求超时和连接错误会作为普通运行时错误返回，可由 `$try/$catch` 捕获

### 风险说明

出站 HTTP 请求会把脚本能力从“读写本地资源”扩展到“主动访问外部系统”。这意味着脚本可以把本地文件、环境变量或计算结果发送到远端服务，因此属于明确的副作用入口。

## 数据库连接与 SQL 查询

### 当前行为

Zun 当前通过原生模块提供数据库访问能力，包括：

- `std.sqlite`
- `std.postgres`
- `Connection.query(...)`
- `Connection.execute(...)`
- `Connection.close()`

这些能力底层走 runtime intrinsic 层，再由 `std.*` 模块暴露给脚本。`std.sqlite` 可访问本地 SQLite 文件或 `:memory:` 数据库；`std.postgres` 会直接使用宿主进程可达的 PostgreSQL 网络连接能力。

### 当前边界

- 数据库路径、连接串与 SQL 语句都由脚本提供
- `std.sqlite` 的访问范围默认受宿主进程文件系统权限约束
- `std.postgres` 的访问范围默认受宿主进程网络可达范围约束
- 没有按驱动、主机、端口、库名或文件路径做白名单限制
- 没有按模块、运行模式或 HTTP handler 区分数据库权限
- 连接、查询、绑定和关闭错误会作为普通运行时错误返回，可由 `$try/$catch` 捕获

### 风险说明

数据库能力同时把脚本扩展到“读写本地数据库文件”和“访问外部数据库服务”。这意味着脚本不仅可以读取敏感业务数据，也可以修改持久化状态，因此属于明确的副作用入口。

## 模块加载与文件系统边界

### 当前行为

Zun 当前支持：

- `$mod a.b`
- `$mod a.*`
- `$HTTP(...).link("a.b")`
- `std.*` 命名空间模块
- HTML 相关的模块式资源链接

模块解析会在当前文件目录、项目根、`modules/`、`deps/`、`stdlib/` 等位置查找实际文件。

### 当前边界

- 模块加载本质上属于文件系统读取能力
- 没有单独的模块访问沙箱
- `std.*` 与项目模块有命名空间区分，但不等于权限隔离
- 模块可访问范围仍由宿主文件系统权限决定

### 风险说明

模块系统当前主要解决“怎么找到文件”，而不是“是否允许访问文件”。

## 当前默认开放能力

以下能力当前视为默认开放：

- 文件读取
- 文件写入与删除
- 环境变量读取
- 标准输入读取
- HTTP 服务监听与路由暴露
- HTTP 出站请求
- 数据库连接与查询
- 模块文件加载

## 未来可能受限的能力

以下入口在未来很可能需要收紧：

- 文件系统读写范围
- 环境变量读取范围
- HTTP handler 能力范围
- HTTP 出站请求目标范围
- 数据库连接目标范围
- 模块加载可访问路径
- 静态文件暴露范围

## 后续可扩展方向

为了给后续安全演进留接口，当前文档明确预留以下方向：

- 可选 runtime policy
- 可选文件系统限制
- 可选环境变量白名单
- 可选 HTTP handler 能力裁剪
- 可选 capability-based runtime

这些方向当前都还没有落地实现。
其中 runtime intrinsic 基础设施已经落地，但策略默认值仍然是 allow-all。
