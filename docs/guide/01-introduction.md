# 1. 认识 Zun

Zun 是一门面向独立开发者的脚本语言，强调“从想法到可运行结果”的路径尽量短。

它当前的用户主线很明确：

- 写脚本
- 组织模块
- 使用标准库
- 直接暴露简单 HTTP 服务

这也是本套 Guide 的组织方式。

## 这套 Guide 怎么读

这组文档分成三层：

- Guide：按学习路径展开，讲如何使用 Zun
- Reference：按主题查表，适合已经入门后回查
- Spec：记录当前实现行为，遇到边界问题以 Spec 和实现为准

如果你第一次接触 Zun，建议按本 Guide 从前往后读。

## Zun 的几个核心特征

### 1. 符号化语法

Zun 使用 `$` 前缀组织大量语言结构：

```zun
$ value = 1;
$@ NAME = "zun";
$>> value;
```

常见形式包括：

- `$` 变量声明
- `$@` 常量声明
- `$fn` 函数
- `$#` 返回
- `$if`、`$while`、`$for` 控制流
- `$mod` 模块导入
- `$GET`、`$POST` 等 HTTP 路由

### 2. 默认解释执行

你可以直接运行 `.zun` 文件，也可以进入 REPL 快速验证代码。

### 3. 默认动态，支持渐进类型

不写类型注解时，变量保持动态。

```zun
$ x = 1;
x = "hello";
```

写了类型注解后，Zun 会对赋值进行约束：

```zun
$ x: Int = 1;
```

### 4. 模块、标准库、HTTP 是主线能力

Zun 不只是“能写表达式”的玩具语言。当前实现已经具备：

- 语言模块系统
- `std.*` 标准库模块
- `package.toml` 项目配置
- `zun serve` HTTP 服务模式

## 为什么 Zun 长这样

旧 guide 里有一个很重要的点，新主线也应该保留：Zun 不是想做“更大、更全”的通用语言，而是想把独立开发者最常见的起步路径压短。

可以把它理解成：

- 少一点工程铺垫
- 少一点框架前置学习
- 多一点脚本即服务的直接路径

## `$` 的设计直觉

`$` 不只是一个视觉符号，它是 Zun 语法风格的中心。

```zun
$ value = 1;
$@ PI = 3.14;
$>> value;
```

这种写法有两个直接效果：

- 代码外形很容易识别
- 初学者更容易把“声明、输出、控制结构”区分开

## 目标用户

按当前定位，Zun 更偏向这些用户：

- 独立开发者
- 需要快速验证 API 或脚本想法的人
- 不想先搭完整框架再开始的人

## 和 PHP 式传统 Web 路线的区别

旧文档里有一句比喻是有效的：PHP 更像建房子，Zun 更像先把摊摆出来。

这不是说工程化不重要，而是说 Zun 当前阶段更强调：

- 今天学
- 今天写
- 今天跑起来

## 当前阶段的方向

从现有文档和实现看，Zun 的方向更接近：

- 脚本
- 小型工具
- 轻量 API
- 配置驱动服务

而不是一开始就进入重框架、重工程、重生态的路线。

## 当前适合用 Zun 做什么

按当前实现，比较合适的场景有：

- 小脚本
- 配置驱动的小工具
- 简单文件与环境变量处理
- 轻量 JSON 处理
- 原型 API 或内部接口

## 这一阶段不应该期待什么

Guide 不会把这些内容写成“已经成熟可用”：

- 完整第三方包生态
- 大型工程化框架
- 尚未固定下来的语法提案
