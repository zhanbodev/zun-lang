# Zun HTTP 扩展设计规范

> 版本：Draft v0.1 · 基于 Zun v0.9
> 状态：设计阶段，尚未实现

---

## 一、设计哲学

Zun 的核心符号是 `$`，代表财富、代表价值、代表「写代码就是赚钱」。

HTTP 扩展延续这一哲学，提出两个核心概念：

- **超函数（Hyper Function）**：以 `$GET` `$POST` 等为代表的 HTTP 函数族，是普通函数 `$fn` 的 HTTP 子类型，天生具备接口能力
- **超函数链（Hyper Chain）**：附加在超函数末尾的链式修饰符，以 `.$` 开头，描述接口的路由、鉴权、限流等元信息

> **声明即部署，函数即接口。**
> 没有框架，没有路由表，没有中间件配置——写完超函数，服务就存在了。

## 二、超函数（Hyper Function）

### 2.1 基本语法

```zun
$METHOD fn_name(params) -> ReturnType {
    $# value;
}
```

### 2.2 超函数族

| 符号 | 类型 | 说明 |
|------|------|------|
| `$fn` | 普通函数 | 内部调用，不暴露为接口 |
| `$GET` | 同步 GET | 查询类接口 |
| `$GET~` | 异步 GET | 需要等待 IO 的查询接口 |
| `$POST` | 同步 POST | 创建类接口 |
| `$POST~` | 异步 POST | 需要等待 IO 的创建接口 |
| `$PUT` | 同步 PUT | 全量更新接口 |
| `$PUT~` | 异步 PUT | 需要等待 IO 的更新接口 |
| `$DEL` | 同步 DELETE | 删除类接口 |
| `$DEL~` | 异步 DELETE | 需要等待 IO 的删除接口 |
| `$PATCH` | 同步 PATCH | 局部更新接口 |
| `$PATCH~` | 异步 PATCH | 需要等待 IO 的局部更新接口 |
| `$WS~` | WebSocket | 持久连接，天然异步，无同步版本 |

### 2.3 同步与异步

`~` 波浪号表示异步身份，`$@` 表示在调用点等待异步结果：

```zun
// 同步超函数
$GET hello() -> String {
    $# "Hello, Zun!";
}

// 异步超函数
$GET~ user(id) -> JSON {
    $ data <- $@db.get("users", $.id);    // $@ 等待异步结果
    $# $.data;
}
```

异步设计原则：**`$@` 在调用点显式标记，函数签名不向上传染。**

### 2.4 返回类型

返回类型声明直接决定响应的 `Content-Type`，无需手动设置响应头：

| 类型 | Content-Type | 说明 |
|------|-------------|------|
| `-> String` | text/plain | 纯文本 |
| `-> JSON` | application/json | JSON 数据 |
| `-> HTML` | text/html | HTML 页面 |
| `-> Stream` | — | 流式响应 |
| `-> File` | — | 文件下载 |
| `-> Blob` | — | 二进制数据 |

### 2.5 保留参数名

超函数的参数自动从请求中映射，以下为保留参数名：

| 参数名 | 来源 | 说明 |
|--------|------|------|
| `body` | Request Body | 自动读取请求体 |
| `file` | Multipart | 自动读取上传文件 |
| `conn` | WebSocket | WebSocket 连接对象（`$WS~` 专用） |
| 其他参数 | Query String | 自动从 query string 映射 |
| 路径参数 | URL Path | 由 `.$R()` 中的 `:param` 声明 |

### 2.6 响应状态码

`$#` 支持状态码前缀，`$##` 专用于错误响应：

```zun
$POST user_create(body) -> JSON {
    $# 201 { "created": true };          // 201 Created
}

$GET user(id) -> JSON {
    $? $.id > 0 {
        $# 200 { "id": $.id };           // 200 OK
    } $! {
        $## 404 { "error": "Not Found" }; // 错误响应
    }
}
```

## 三、超函数链（Hyper Chain）

超函数链是附加在超函数末尾的链式修饰符，描述接口的元信息。

### 3.1 基本语法

```zun
$GET hello() -> JSON {
    $# "Hello";
}
.$R("/api/hello")
.$AUTH()
.$LIMIT(100)
```

超函数链以 `.$` 开头，每个修饰符独占一行，可自由组合，顺序不影响结果。

### 3.2 修饰符列表

| 修饰符 | 说明 | 示例 |
|--------|------|------|
| `.$R()` | 路由路径，必填 | `.$R("/api/user/:id")` |
| `.$HDR()` | 读取请求头字段 | `.$HDR("Authorization")` |
| `.$AUTH()` | 开启鉴权校验 | `.$AUTH()` |
| `.$LIMIT()` | 限流，每分钟最大请求数 | `.$LIMIT(100)` |
| `.$V()` | API 版本号 | `.$V("v1")` |

### 3.3 `.$R()` 路由规则

路径参数使用 `:param` 声明，与超函数参数同名自动映射：

```zun
$GET user(id) -> JSON {
    $# { "id": $.id };
}.$R("/api/user/:id")
// :id 自动映射到参数 id
// 其余参数映射到 query string
```

### 3.4 `.$HDR()` 请求头读取

读取指定请求头字段，注入为 `$HDR` 对象：

```zun
$GET~ profile(id) -> JSON {
    $ token <- $HDR.Authorization;
    $# { "id": $.id, "token": $.token };
}
.$R("/api/profile/:id")
.$HDR("Authorization")
```

`.$HDR()` 声明要读取的字段，`$HDR.字段名` 在函数体内访问其值。

## 四、完整示例

### 4.1 基础 CRUD

```zun
PORT <- 3000;
PREFIX <- "/api";

// 查询用户
$GET~ user(id) -> JSON {
    $ data <- $@db.get("users", $.id);
    $# $.data;
}
.$R("/api/user/:id")
.$AUTH()

// 创建用户
$POST~ user_create(body) -> JSON {
    $ result <- $@db.insert("users", $.body);
    $# 201 { "created": true, "data": $.result };
}
.$R("/api/user/create")
.$AUTH()

// 更新用户
$PUT~ user_update(id, body) -> JSON {
    $ result <- $@db.update("users", $.id, $.body);
    $# $.result;
}
.$R("/api/user/:id")
.$AUTH()

// 删除用户
$DEL~ user_delete(id) -> JSON {
    $@db.delete("users", $.id);
    $# { "deleted": true };
}
.$R("/api/user/:id")
.$AUTH()
```

### 4.2 公开接口 + 鉴权接口组合

```zun
// 无需鉴权
$GET hello() -> String {
    $# "Hello, Zun!";
}
.$R("/api/hello")

// 需要鉴权 + 限流
$GET~ dashboard(uid) -> JSON {
    $ data <- $@db.get("dashboard", $.uid);
    $# $.data;
}
.$R("/api/dashboard/:uid")
.$HDR("Authorization")
.$AUTH()
.$LIMIT(200)
```

### 4.3 WebSocket

```zun
$WS~ chat(conn) -> Stream {
    $@> msg <- $@conn.receive() {
        $>> "收到消息: " + $.msg;       // 打印到终端
        $@conn.send("echo: " + $.msg);  // 回传给客户端
    }
}
.$R("/ws/chat")
.$AUTH()
```

### 4.4 文件上传

```zun
$POST~ upload(file) -> JSON {
    $ path <- $@storage.save($.file);
    $# { "url": $.path };
}
.$R("/api/upload")
.$AUTH()
.$LIMIT(50)
```

## 五、`$` 家族全景

Zun 所有能力均从 `$` 生长，无例外：

```
变量与常量
  $              变量声明
  $&             常量声明
  $.             变量读取

输入输出
  $>>            stdout 输出（终端，不进入响应）
  $#             函数返回值 / HTTP 响应体
  $##            HTTP 错误响应（带状态码）

流程控制
  $?             条件判断（if）
  $!             否则（else）

函数家族
  $fn            同步普通函数
  $fn~           异步普通函数

超函数族（HTTP）
  $GET   $GET~
  $POST  $POST~
  $PUT   $PUT~
  $DEL   $DEL~
  $PATCH $PATCH~
  $WS~           WebSocket（仅异步）

异步原语
  $@             await，等待异步值落地
  $@>            异步迭代（流式数据）

内建对象
  $HDR           请求头只读对象（由 .$HDR() 注入）

超函数链修饰符
  .$R()          路由路径
  .$HDR()        声明读取的请求头字段
  .$AUTH()       鉴权
  .$LIMIT()      限流
  .$V()          版本号
```

## 六、API 场景覆盖率

| 场景 | 支持情况 | 实现方式 |
|------|---------|---------|
| 基础 CRUD | ✅ | `$GET` `$POST` `$PUT` `$DEL` |
| 异步 IO | ✅ | `$GET~` + `$@` |
| 调用外部 API | ✅ | `$@fetch()` |
| 鉴权校验 | ✅ | `.$AUTH()` |
| 限流 | ✅ | `.$LIMIT()` |
| 读请求头 | ✅ | `.$HDR()` + `$HDR.字段名` |
| 状态码控制 | ✅ | `$# 201` / `$## 404` |
| 流式响应 | ✅ | `-> Stream` + `$@>` |
| 文件上传下载 | ✅ | `-> File` + `file` 保留参数 |
| WebSocket | ✅ | `$WS~` + `conn` 保留参数 |

## 七、运行方式

```bash
# 启动 HTTP 服务
zun serve api.zun

# 指定端口
zun serve api.zun --port 8080

# 启动时自动打印路由表
# -> Zun serving on http://localhost:8080
# -> GET    /api/hello
# -> GET    /api/user/:id
# -> POST   /api/user/create
# -> WS     /ws/chat
```

## 八、与传统方案的对比

| 特性 | Zun HTTP | Express.js | FastAPI |
|------|-------------|------------|---------|
| 路由声明 | 函数即路由 | 手动配置 | 装饰器 |
| 鉴权 | `.$AUTH()` | 中间件 | 依赖注入 |
| 限流 | `.$LIMIT()` | 第三方库 | 第三方库 |
| 异步 | `$@` 原语 | async/await | async/await |
| 学习成本 | 极低 | 中等 | 中等 |
| 目标场景 | 快速验证 | 通用 Web | API 服务 |

## 九、设计优势

1. **声明即部署**：写完超函数，服务就存在了
2. **极简路由**：无需学习路由配置语法
3. **一体化**：函数定义 + 路由绑定一步完成
4. **快速验证**：一行代码就是一个 API
5. **符合定位**：让「变现」成为语言的一等公民
